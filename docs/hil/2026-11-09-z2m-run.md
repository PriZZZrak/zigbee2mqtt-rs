# Upstream z2m oracle run (2026-11-09)

Ran the pinned upstream `zigbee2mqtt` 2.14.3 + `zigbee-herdsman` 11.2.0 in the
dev container against the real Sonoff Dongle Plus, using the router's
`database.db` / `state.json` / `coordinator_backup.json` and `configuration.yaml`.

## Setup

- Node v24.22.2, `pnpm` 11.26.0
- Upstream checkout: `.upstream/zigbee2mqtt` (commit `3c841fdf`), built with
  `pnpm install --frozen-lockfile && pnpm build`
- Data dir: `/tmp/opencode/z2m-run` (copy of `/etc/zigbee2mqtt` from the router)
- Config changes for the isolated run:
  - `serial.port: /dev/ttyUSB0`
  - `mqtt.server: mqtt://192.168.0.1`
  - `mqtt.base_topic: zigbee2mqtt-hil`
  - `homeassistant.enabled: false`
  - `frontend.enabled: false`
  - `advanced.log_output: [console]`

The router z2m was left untouched; a separate base topic avoided bridge-state
conflicts.

Exercised over MQTT:

- `bridge/info`, `bridge/devices`, `bridge/groups`, `bridge/definitions`;
- `bridge/request/networkmap` → raw map with 5 nodes / 10 links;
- `bridge/request/permit_join` true/false → both `status: ok`;
- `bridge/request/health_check` → `{"healthy":true}`;
- `Термостат кухня/get {"local_temperature":""}` → updated state;
- `Датчик температуры` state updates.

Shutdown was graceful and wrote a fresh unified backup:

This confirms the `source` string used by our `to_unified_backup` port.
