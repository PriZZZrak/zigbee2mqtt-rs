# EVID-04 — reference/differential harness

Implementation: `scripts/evid04_harness.py`, smoke fixture
`scripts/tests/fixtures/evid04_smoke/temperature.json`, fake reference
`scripts/tests/fake_evid04_reference.py`, tests
`scripts/tests/test_evid04_harness.py`, CI step in `.github/workflows/rust-ci.yml`.

## Contract

A fixture is a JSON file:

```json
{
  "id": "case-id",
  "ignore": ["last_seen", "*.private"],
  "sort": ["actions"],
  "input": { "...": "..." }
}
```

The reference and candidate commands receive the fixture `input` on stdin and
must print JSON. The harness compares the outputs after:

- removing only explicitly listed dotted paths (`last_seen`, `nested.field`,
  `*.private` style wildcards);
- sorting only explicitly listed arrays by canonical JSON.

There is no implicit sorting, timestamp stripping or numeric tolerance. A
mismatch prints both normalized values and exits non-zero; a machine-readable
report is written with `--report`.

## Pins

`--lock docs/parity/upstream-lock.json` loads baseline commits and compares them
with `.upstream/<repo>` HEADs. Missing checkouts or differing commits are
`UNVERIFIED`/`MISMATCH`. `--require-pins` fails in that case. CI runs the fixture
smoke with `--skip-pins` because reference checkouts are not present; a dedicated
reference job must use `--require-pins` when they are.

## Commands

```bash
# Validate the harness only (fake reference, NOT parity evidence)
python3 scripts/evid04_harness.py \
  --fixtures scripts/tests/fixtures/evid04_smoke \
  --reference-cmd "python3 scripts/tests/fake_evid04_reference.py reference" \
  --candidate-cmd "python3 scripts/tests/fake_evid04_reference.py candidate" \
  --skip-pins --report /tmp/evid04-smoke.json

# Real reference run (once Node/pnpm and pinned checkouts exist)
python3 scripts/evid04_harness.py \
  --fixtures docs/parity/evidence/evid04/fixtures \
  --reference-cmd "./scripts/run-node-reference.sh" \
  --candidate-cmd "./scripts/run-rust-candidate.sh" \
  --require-pins --report docs/parity/reports/evid04.json
```

The fake reference deliberately differs in the ignored timestamp and array order;
the smoke case proves normalization and mismatch handling, not Zigbee2MQTT
behavior.

## Real reference run (2026-11-04)

Node and pnpm were obtained locally (Node v22.14.0, corepack-resolved pnpm) and
the pinned converters checkout was installed and built:

```text
.upstream/zigbee-herdsman-converters @ 9dabbe4e343573c5a3070605efd843a1b3a16058
pnpm install --frozen-lockfile  -> ok
pnpm run build                  -> 4560 definitions, dist/models-index.json
```

Reference driver: `scripts/evid04_node_reference.js` resolves the definition
through `models-index.json` (same lookup as upstream `getFromIndex`) and runs the
matching `fromZigbee` converter. Candidate driver: `src/bin/evid04_candidate.rs`
runs the same conversion through the Rust converter host and a staged package
(`zcl-commands.json` generated by `scripts/gen-registry.mjs`).

```text
python3 scripts/evid04_harness.py \
  --fixtures docs/parity/evidence/evid04/fixtures \
  --reference-cmd "env HC_CONVERTERS_DIST=$PWD/.upstream/zigbee-herdsman-converters/dist node scripts/evid04_node_reference.js" \
  --candidate-cmd "env EVID04_CACHE=/tmp/opencode/evid04/herdsman-converters/v26.115.1 ./target/release/evid04_candidate" \
  --require-pins --report docs/parity/reports/evid04.json

EVID-04: 3 passed, 0 failed,
pins=[('zigbee2mqtt','MATCH'),('zigbee-herdsman','MATCH'),
      ('zigbee-herdsman-converters','MATCH'),('frontend','MATCH')]
```

Fixtures (SONOFF SNZB-02): `temperature` 2250 → `{"temperature":22.5}`,
`humidity` 5020 → `{"humidity":50.2}`,
`batteryPercentageRemaining` 180 → `{"battery":90}`. Both sides produced
identical JSON; the report is checked in at `docs/parity/reports/evid04.json`.

Provenance nuance: the converters package lock resolves **herdsman 10.9.5**,
while the app baseline lock pins **10.10.0**. The reference above therefore uses
the converters' own resolution for the converter call; the app-level 10.10.0
runtime is not exercised. `upstream-lock.json` already records this distinction.

## Validation in this environment

- `python3 -m unittest discover -s scripts/tests` → **29 passed**, including
  normalization, wildcard ignore, pass/mismatch exit codes and pin
  MATCH/MISMATCH against a temporary git repository.
- `python3 scripts/evid04_harness.py ... --skip-pins` → `PASS 1 0` (fake smoke).
- Real differential run above: 3 fixtures, all pins MATCH.
- CI runs the Python tests and the fake smoke (no network/checkouts), uploading
  `evid04-smoke.json`; the real run is reproducible with the commands above.

## Gaps

- Only one device model (SONOFF SNZB-02) with three attribute-report fixtures has
  a real differential; no MQTT, ZCL wire, storage, groups, OTA or frontend
  differentials yet.
- The reference uses converters' herdsman 10.9.5, not the app's 10.10.0.
- Real runs need network + built checkouts; CI keeps only the fake smoke.
- Report contains absolute paths from the capture environment.
- The harness does not start a broker, coordinator or Home Assistant; it compares
  command JSON only. Integrations need separate drivers feeding raw artifacts.
- CI's smoke step is explicitly named as fake and must not be counted as parity.
