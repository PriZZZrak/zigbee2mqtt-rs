## Differential status

- The upstream suites above run green and are the behavioural oracle for the
  ported surface.
- Rust counts are intentionally behavioural slices rather than a 1:1 port of
  upstream mock-heavy unit tests; every ported file has integration tests that
  assert observable MQTT payloads, discovery topics, responses and logs.
- Differences tracked in `docs/parity-matrix.md`: approved bridge OMITTED
  handlers and deferred Windfront static assets.
  `bridge/info.os.node_version` reports the real Rust toolchain version
  (`rustc X.Y.Z`, captured by `crates/z2m-rs/build.rs`) instead of Node's
  `process.version`; there is no Node runtime in this build.
- Availability timers are now asserted on a paused Tokio clock
  (`passive_device_publishes_offline_after_timeout_and_online_on_last_seen`,
  `device_timeout_option_controls_the_timer`) instead of upstream fake timers.
- HA action parsing is asserted 1:1 against the upstream `it.each` table
  (`extension::homeassistant::action_value_tests::parses_action_names_like_upstream`,
  26 cases), and expose/device-option overrides by
  `applies_expose_metadata_and_null_name`,
  `applies_device_option_overrides_and_null_filtering` and
  `device_option_homeassistant_false_disables_discovery`.
- HA discovery cleanup/rename/OTA/last_seen paths are now asserted by
  `clears_outdated_discovery_config_from_retained_messages`,
  `keeps_discovery_topics_when_rename_is_not_a_homeassistant_rename`,
  `discovers_ota_update_entity_when_definition_has_ota` and
  `discovers_last_seen_when_continuous_format_is_enabled`.
- Remaining per-case work is `code`-class only (ported, no dedicated
  assertion), plus adapter/HIL and approved omissions - see
  `docs/extension-test-cases.md`.
